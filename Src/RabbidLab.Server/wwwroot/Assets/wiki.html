Rabbid Lab runs on one server, and admins use it in a browser. Install it on a computer that is always on.

On Windows

  1. Download RabbidLab-Setup-<version>.exe from the latest release on GitHub.
  2. Run it and select Yes at the User Account Control prompt.
  3. Select the installation folder and shortcuts, then the address (port 8420 by default), then the HTTPS certificate. Rabbid Lab can create its own certificate or use an existing one.
  4. Select Install. Rabbid Lab is installed as a Windows service and starts immediately.
  5. Open https://localhost:8420 on the server, or https://<server name>:8420 from another computer.

Running Setup again updates Rabbid Lab. Its settings are kept.

In Docker

  1. Run docker compose up -d in the repository folder.
  2. Open http://<host>:8420. All Rabbid Lab data is stored in the rabbidlab volume.

Next: complete the first-time setup.

The first time Rabbid Lab is opened, it asks how users sign in. Complete this step immediately after installation. Until it is complete, anyone who can reach the port can complete it.

With Active Directory

  1. On the setup page, use the Active Directory form. If the local account form is shown, select Use Active Directory instead.
  2. Check the domain name. Leave Domain controller set to Automatic unless you need a specific domain controller.
  3. Enter your own domain account and password, then select Connect and sign in. Your account becomes an Administrator, and all domain users can sign in with the User role.

With a local account

  1. Select Use a local account instead.
  2. Enter a username and password, then select Create account. This account is the first Administrator.

To set which users have which permissions, see Roles.

All pages are in the navigation pane on the left. You see only the pages your roles allow.

  • Lab: Overview, Links (the sites in your lab), Sensors, Devices (computers with the client, their local accounts and their local administrators) and Network.
  • Directory: Active Directory (Users, Groups and Computers in your domain), Group Policy, Domain health and Sync.
  • Alerts and Automation: Alerts and Workflows.
  • Help: this wiki. What's new and GitHub are in the top bar.
  • Settings, at the bottom: your account, updates, Roles and people, sign-in, alerts, the activity log and server settings.

The top bar also has shortcuts to Updates and Activity. Your name in the top right shows how you signed in and has Sign out. Collapse, at the bottom of the navigation pane, reduces it to icons.

Computers in Devices, users, groups and computers in Active Directory, and GPOs each have a Notes tab in their side panel. The number on the tab is the number of notes.

  • Type in the box, then select Add note or press Ctrl+Enter. The toolbar supports bold, italic, underline, strikethrough, headings, quotes, lists, code and links (Ctrl+K). Pasted text is inserted as plain text.
  • Anyone who can view the computer, account or GPO can read its notes and add a note. Notes stay with an AD object when it is moved or renamed.
  • Use the pencil to edit your own notes and the bin to delete them. Users with permission to change that type of object can delete any note on it.
  • Adding, editing and deleting notes is recorded in the activity log.

A computer appears under Devices after the Rabbid Lab client is installed on it. No key is required: the client needs only the server address. New computers show as Pending approval until an admin approves them.

From the computer (recommended)

  1. On that computer, open Rabbid Lab in a browser and sign in.
  2. The bar at the top says This computer is not connected. Select Download the client and run the MSI.
  3. Select Connect this computer. The client opens with this server's address filled in.
  4. Check the address, select Connect, and select Yes at the User Account Control prompt.
  5. Approve the computer under Devices.

When the server's certificate changes

The client checks the server by its certificate's key. The server also has an identity key of its own, kept with the rest of its data, and each check-in gives the client its public half. If the certificate is replaced with a new key, the client asks the server to sign a random number together with the key it shows now, checks that signature against the identity it keeps, and then takes the new key and reconnects by itself. Nobody posing as the server can make that signature. A client that last checked in before 1.1.377 has no identity yet, so after a key change it still needs Connect this computer once.

A fingerprint set by Group Policy is never replaced: update the policy instead.

Silent install, from a command line or Intune

  1. Open Devices and select New in the bar under the banner, or select Add computers from its arrow.
  2. Copy the install command. It contains this server's address and public key fingerprint, which the client uses to verify the server.
  3. Run it on the computer, or enter it in Intune as the install command.

With Group Policy

  1. Open Devices > Deploy the client. This requires the Add computers and Create and edit GPOs permissions, and Group Policy Management on this server.
  2. Select the server address that computers connect to. A fully qualified name, such as helpdesk.yourdomain.com, works anywhere in the domain.
  3. Select Deploy to all computers and verify your identity. Rabbid Lab creates the Rabbid Lab Client GPO, copies the installer to its SYSVOL folder, adds a task that silently installs the client as SYSTEM on computers that do not have it, excludes the client from Defender attack surface reduction rules, and links the GPO to the domain.
  4. Each computer installs the client at its next Group Policy refresh, within about 90 minutes, with no restart. Signed-in users see nothing: no installer window, no tray icon and no messages (the installer runs with QUIET=1). New computers show as Pending approval under Computers.

Deploy again updates the installer in the GPO after a Rabbid Lab update. Stop deploying stops the GPO from applying to the domain; computers keep the client. If Intune manages Defender, the page shows the exclusion to add to your attack surface reduction policy.

With your own GPO

In Add computers, download the MSI and the Group Policy template. Assign the MSI under Software Installation, and set Server address under Administrative Templates > Rabbid Lab > Client.

Group Policy settings take precedence over settings from the installer or from Connect.

  1. Open Devices. New computers show as Pending.
  2. Select Approve on the computer's row. The computer stays connected after it is approved.
  3. To remove a computer, select it, then select Actions > Remove from Devices in the panel on the right. If the client is still installed, the computer reconnects and needs approval again.

To approve new computers automatically, set Require approval for new computers to Off in Add computers. New computers then connect immediately.

The views under Computers on the left (Online, Offline, Pending approval and others) filter the list.

Each computer's client reports its model, serial number, processor, memory, drives, uptime, whether a restart is pending, its installed software, and its installed and missing Windows updates. Collecting this information does not install or change anything on the computer.

  • Computers shows a summary on each row. The views on the left list computers that need attention: Needs updates, Needs restart, Low disk space (less than 15% free on C:), Has errors and Client out of date. To add columns, use Choose columns.
  • Select a computer to view its hardware, with tabs for its installed software and its Windows updates. To list software across all computers, run a WMI query.
  • Export saves the current list as a CSV file.

The client collects inventory every 30 minutes and sends it when something changes. It checks Windows Update for missing updates every six hours; antivirus definition updates are excluded. Requires client 1.1.165 or later.

On Devices, you can run scripts on computers, install missing Windows updates, or restart computers. Scripts are written in PowerShell or Command and run as SYSTEM.

  • Several computers: tick them, then select Actions. Shift-click selects a range.
  • One computer: select it. Actions at the top of its panel has the same menu, and its Jobs tab lists the jobs that ran on it.
  • Scripts is the script library. While Scripts is open, New creates a script (it is also in the New menu), and Start from fills in a common script for you to edit. Each script has a time limit and is stopped when the limit is reached.
  • The built-in domain scripts are read-only: Domain trust (secure channel), Domain controller in use, List domain controllers, Domain trusts, Script run-as account, and Domain report, which runs all of them. Domain trust fails the job when the computer's secure channel with the domain is broken.
  • Jobs lists every run. Select a job to view each computer, its exit code, the script output and the exact script that ran.
  • Lock returns signed-in users to the sign-in screen with their apps still open. Sign out all users signs them out immediately. Send a message shows a message to signed-in users. These actions and Shut down run immediately: a computer that is offline for more than 15 minutes does not receive them later.
  • Restart gives signed-in users a five-minute warning. Windows updates installs missing updates but does not restart: computers that need a restart are listed under Needs restart.
  • An offline computer receives a job when it is back online, for up to one day. After that, the job status is Expired.
  • Wake uses Wake-on-LAN to turn on a computer that is shut down or asleep. This server sends the packet to computers on its own network. For a computer on another network, an online computer on that network relays it. Wake-on-LAN must be enabled in the BIOS and in Windows: the computer panel shows which settings are missing, and the built-in script Enable Wake-on-LAN configures the Windows settings.

Verify your identity. Before a job runs, or a script or workflow is saved, you are asked for a code from your authenticator app, or for your password if MFA is not set up. You are asked again after 10 minutes. To run a job on more than 10 computers, you also enter the number of computers.

Permissions. Four permissions under Devices in Roles and people control this: Restart, wake and update computers; Run scripts; Manage scripts; and Manage workflows. Manage scripts allows running any code on every computer, so assign it to as few people as possible. Every run is recorded in the activity log with who ran it and the script's SHA-256 hash.

To block scripts and actions on specific computers, set Allow scripts and actions to Disabled in the Group Policy template. Their jobs then show as Rejected. Computers need client 1.1.168 or later to run jobs.

A workflow runs steps on computers automatically. Open Workflows under Devices and select New, or select New workflow from the New menu.

  • When: a new computer is approved; on a schedule (days and a time, in this server's time zone); or a computer comes online, has missing Windows updates, needs a restart, or is low on space on C:.
  • Computers: all computers, names that match a pattern such as SHOP-*, computers whose Windows version contains (or does not contain) a word such as Server, or only computers with no signed-in user.
  • Steps: run a script from the library, install missing Windows updates, restart, or restart if a restart is pending. Steps run in order on each computer, and the workflow stops at the first step that fails.
  • Run now starts the workflow on every approved computer it applies to. Disable keeps the workflow without running it.

Each run is a job under Jobs, listed as a workflow. A scheduled run reaches a computer that was offline if the computer comes back online within four hours. A workflow can contain only steps that its creator has permission to run.

The client is a Windows service with a tray icon. It checks in every minute, reports the signed-in user, updates itself to the server's version, and makes the local account changes you request on a computer's Accounts tab in Devices.

  • Client window: select the tray icon, or open Rabbid Lab Client from the Start menu. It shows the connection status, the server, the signed-in Windows user, both versions and the last check-in.
  • Tray icon: shown as soon as the client is installed manually. After a silent install (Intune, Group Policy), it appears at the next sign-in.
  • Not connected to a server? The window has Connect to a server.
  • Block account changes on specific computers: in the Group Policy template, set Allow account changes to Disabled.
  • Block scripts and actions on specific computers: in the same template, set Allow scripts and actions to Disabled.
  • Hide the client from users: set Hide the client from signed-in users to Enabled, or install with QUIET=1 (the deploy GPO does this). There is no tray icon and there are no messages; the client still connects and needs approval. Disabled shows the icon even after QUIET=1.

If a computer does not accept changes, see Computer does not accept changes.

After a computer connects to a server, the client is locked on it: Windows cannot uninstall it from Installed apps or from the Rabbid Lab Client window. An administrator on the computer can still stop the service; the lock applies only to uninstalling. A client that has never connected to a server is not locked.

  1. Open Devices and select the computer. It opens in a panel on the right.
  2. Uninstall now makes the client uninstall itself within a minute. The computer then shows as Offline: select Actions > Remove from Devices to remove it from the list.
  3. Or select Allow for an hour so that a user on the computer can uninstall the client. Lock again ends that period early.

When the computer cannot reach the server

  • Uninstall code. Each computer has its own code. Select Show code under Uninstall code in the same panel. On the computer, open Rabbid Lab Client, select Uninstall and enter the code. Uninstalling is then allowed for one hour, with no connection required. Showing and using a code are both recorded in the activity log, and using a code is also recorded in the computer's Windows event log.
  • 30 days offline. A computer that has not reached this server for 30 days is unlocked automatically, so computers are not left locked if the server is permanently removed. To change this, use Release the lock after 30 days offline in Settings > Devices.

Before you remove the server

First uninstall the client from the other computers with Uninstall now. After the server and its data are removed, uninstalling cannot be allowed and the uninstall codes are lost, so those computers stay locked for 30 days. The Remove page in Setup shows how many computers still have the client. The client on the server itself is uninstalled with the server.

When the server has been removed

Remove-RabbidLabClient.ps1, in the Tools folder of the Rabbid Lab GitHub repository, removes the lock and uninstalls the client. It requires administrator rights on the computer and writes an entry to the Application event log.

  • One computer. Run it on that computer in PowerShell as administrator.
  • Several computers that are on. Run it from one computer with -ComputerName and the computer names. PowerShell remoting must be enabled on the target computers. Computers that do not respond are listed.
  • Computers that are off. Add it to a new GPO in Group Policy Management as a startup script: Computer Configuration > Policies > Windows Settings > Scripts > Startup > PowerShell Scripts. Each computer runs it at its next startup. Computers without the client are not affected.

If you deployed the client with Group Policy, delete the Rabbid Lab Client GPO first. Otherwise it reinstalls the client wherever it is missing.

A locked computer cannot connect to a different server until it is unlocked. The lock blocks the standard ways of removing the client. An administrator on the computer can still remove it manually, and the computer then shows as Offline.

Rabbid Lab makes all Active Directory changes as a dedicated service account. Its password is stored encrypted on the server. You set it up once.

Select a type

  • Delegated (svc-rabbidlab): a standard account with Full Control over user, group and computer objects in the OUs you select, like the Delegation of Control Wizard. Group Policy changes and push installs ask for domain admin credentials each time.
  • Domain admin (svc-rabbidlab-admin): a member of Domain Admins, so nothing asks for another sign-in. This server then holds domain admin permissions. Select the check box to confirm that you understand the risk.

The questions under the two types explain what the account is used for, what it is never used for, and where the password is stored. The answers match the selected type.

Create the account

  1. Open Users and select Set up.
  2. Select Delegated or Domain admin.
  3. For Delegated, select the OUs to manage: the entire domain, or one OU, from the list or with Browse….
  4. Enter a domain admin username and password. These credentials are used once to create the account and are not stored.
  5. Select Test sign-in to check the credentials. Nothing is changed.
  6. Select Create.

The password is 64 random characters and is never shown. For svc-rabbidlab-admin, Rabbid Lab changes the password every 30 days.

Use an existing domain admin account

Select Domain admin, then Use an existing account. Enter the account and its password. The account must be a member of Domain Admins. You manage its password: Rabbid Lab stores it and does not change it.

Not now

Not now on the setup card enables read-only mode for the whole server, after you verify your identity. Only admins whose role can set up the service account can enable it. Those admins, and users whose role has View in read-only mode, can view the Active Directory pages within their role's scope. Other users cannot until the service account is set up. In read-only mode, the pages read the domain as this server's computer account, which can read most of the directory, and no changes can be made until the service account is set up. Group Policy changes still work with domain admin credentials. Enabling or disabling read-only mode is recorded in the Activity log. To exit read-only mode, select Disable read-only in Settings > Active Directory.

Select an OU

Browse… beside any OU list opens Select an OU, with the OUs listed on the left. An OU that contains other OUs expands when you select it. Type in Find an OU to search, then select Use this OU, or double-click the OU.

When sign-in fails

The server tests the service account every 15 minutes. If the password is rejected, or the account is locked out, disabled or expired, the Active Directory pages switch to read-only: lists and searches still work, read with this server's computer account, and changes are refused. The alert Service account stopped working is sent, and Settings > Active Directory shows the problem with the button that fixes it:

  • Repair: resets the password to a new random value.
  • Unlock and test: unlocks the account.
  • Enable and test: enables the account and clears its expiration date.
  • Update password: for an account you manage, enter its new password.

Repair, Unlock and Enable ask for domain admin credentials once and do not store them. Each one tests sign-in afterwards.

Change the settings later

Settings > Active Directory (the gear at the bottom of the views on any Active Directory page opens it) has Test, Change… to switch between Delegated and Domain admin, Change now for the password of svc-rabbidlab-admin, the default OUs for new users, groups and computers, and Disconnect. Disconnecting deletes the stored password. The account and its permissions remain in AD until you delete them in Active Directory Users and Computers, and so does the previous account after you switch types.

A delegated account can view admin accounts protected by AdminSDHolder (members of Domain Admins and similar groups) but cannot change them.

  1. Open Users and select New in the bar under the banner. Its arrow has New user, New group and New computer on every Active Directory page.
  2. Enter the first and last name. The display name and username are filled in automatically; you can change them.
  3. Select the OU, and optionally enter an email address, job title and description.
  4. Leave Generate password selected, or select Enter password.
  5. Leave User must change password at next sign-in selected so that the user sets their own password.
  6. Optionally add groups, then select Create account.
  7. Copy the password that Rabbid Lab shows. It is shown only once and is not stored.
  1. Open Users > Locked out, or find the user in All users.
  2. Select the user to open their panel.
  3. If the account is locked out, select Unlock.
  4. If the user forgot their password, select Reset password, select Generate password or enter a password, and leave User must change password at next sign-in selected. Resetting the password also unlocks the account.
  5. Copy the new password and give it to the user.

Select a row anywhere in the console (Users, Groups, Computers, Domain health, AD audit, Recycle Bin, Devices, Roles and people) to open it in a panel on the right. The panel shows the object's details, its groups (and a group's members), and buttons for common changes. Select the round › on the panel's edge, or the row again, to collapse the panel to a narrow strip on the right; select the strip or the row to expand it again. Each row also has a menu with every available change: open it from ⋯ at the end of the row, or right-click the row.

  1. To change several objects at once, tick them on the left (Shift-click selects a range), then select Actions in the toolbar. It shows how many are selected.
  2. Select a category: Account (enable, disable, unlock, expiration), Password, Groups, Security or Organization (edit properties, rename, move).
  3. Groups have Members (add, remove, copy from or to another group) and Member of. Computers have Account, Groups and Organization.
  4. The menu lists only the actions that apply. With several objects selected, each item shows how many of them it applies to.
  5. The panel's Attributes tab lists every attribute of the user, group or computer in Active Directory, as ADSI Edit shows them. Search filters the list, Show empty adds attributes with no value, and Export saves them as a CSV file. Each row's ⋯ (or a right-click) copies the attribute and, with the Edit attributes permission, edits or clears it. Attribute browser opens the same object in the Attribute browser.
  6. In the panel, Member of and a group's Members have a tick on each row and Select all above them. Tick some, then select Remove to remove them all at once; you are asked to confirm when more than one is selected. The cross on a row removes only that one.
  7. Add to groups, Add members and the remove and copy actions show a list with a tick on each item. Search to filter it, tick as many items as you need (Select all shown ticks every item in the filtered list), and the count shows at the bottom. Groups the object is already a member of, and existing members, are not listed.

Protected and built-in accounts and groups can also be changed; Active Directory rejects any change the service account does not have permission to make. Some actions are never offered: changing the password or sign-in settings of the Rabbid Lab service account, or deleting it (it would lock itself out); disabling, moving or deleting a domain controller; and deleting a built-in group. Every change is recorded in the Activity log.

The bar above a list filters it:

  • The search box searches every column. Select a column in front of it to search only that column, and contains, is or starts with.
  • Each chip after it (Status, Department and so on) lists the column's values with the number of rows for each. Tick the values you want. The counts reflect the other filters.
  • Add/remove filters sets which columns have a chip. A star keeps a column at the top of that list.
  • The arrow at the end of the bar expands all chips side by side, so you can tick values without opening each one. The magnifier above a column searches for a value in it.
  • The save button saves the current filter under Load filter, in this browser, with a name you choose. The pencil beside a saved filter renames it and the × deletes it. Advanced filter, in the same menu on Users, Groups, Computers and the Devices list, handles conditions a chip cannot: older than a number of days, does not contain, member of a group, and any or all of several conditions.
  • Clear removes all filters.

The list has its own bar:

  • Actions applies to the ticked rows, and shows how many are selected.
  • Group by groups the rows under a heading for each value of the selected column, with a count. Select a heading to collapse or expand it. Select two columns to create nested groups.
  • The two buttons after the count switch between Compact rows (the default) and Relaxed rows.
  • Select a column name to sort by it, and select it again to reverse the order. The ⋮ beside it sorts, pins the column to the left or right so it stays in place when the list scrolls horizontally, groups by the column or hides it. Autosize all columns fits every column to its contents, and Choose columns sets which columns show. Drag the edge of a column name to resize the column; double-click the edge to fit the column to its contents.
  • The button at the end of the column names sets which columns the list shows, such as email, job title, office, manager, OU or password dates. Reset columns, order, widths and sort restores the defaults.

Every table in the console works the same way: Domain health, AD audit, Recycle Bin, Group Policy, the Attribute browser and the lists under Devices. Drag a column heading onto another to move the column. Columns, order, widths, sort and grouping are saved in this browser for each table; Compact or Relaxed is one setting for all tables.

When a user leaves, disable their account first. A disabled account can be enabled again; deleting cannot be undone.

  1. Open the user's panel in Users.
  2. Select Actions > Account > Disable account. The user is then listed under Disabled.
  3. When you are sure, open the user's panel again, select Actions > Delete…, and confirm.

A user's panel has a Given by Rabbid Lab tab. It lists what Rabbid Lab gave that user, by hand or in a workflow: the account it created and each group it added. Each entry shows who made the change and when.

  • Given by Rabbid Lab: what the user still has.
  • Found, not given by Rabbid Lab: groups the user is in with no record here. They were added in another tool, or before this was recorded. Offboarding removes these too.
  • Taken back: what was removed again, with who removed it and when.

The record starts with this version. Changes made earlier are listed under Found.

Lifecycle, under Automation, lists what is dated, soonest first:

  • New users and other workflow runs saved for a date, with each step. Run now runs one early and Cancel removes it.
  • Offboardings with their stages. Select one to open the user's Offboarding tab.
  • Accounts that expire in the next 14 days with no offboarding scheduled. Offboard… schedules one.

Run a workflow on a date

  1. Select New user on the Lifecycle page, or Run on a workflow under Workflows.
  2. Fill in the fields.
  3. Under When, select On a date and set the date and time.
  4. Select Schedule.

The run happens at that time with your permissions as they are then. If the workflow was deleted or disabled, or you no longer have a permission one of its steps requires, the run fails and says why. Run it again or cancel it from the Lifecycle page.

Connected apps reads the accounts, groups and roles in other apps, matches each account to an Active Directory user, and gives groups and roles there to the members of Active Directory groups. Nothing changes in an app until an access rule gives something, and every change is listed first.

Connect an app

  1. Select Connect an app and select the kind.
  2. Enter a name and the settings for that kind.
  3. Select Connect. The app is read once. If that fails, nothing is saved and the reason is shown.
  • SCIM 2.0: the base URL (https) and a bearer token. For any app with a SCIM endpoint.
  • Google Workspace: the domain, an admin to act as, and the JSON key of a Google Cloud service account with domain-wide delegation for the scopes admin.directory.user and admin.directory.group.
  • PowerShell scripts: for any other app, such as an ERP or a database. See below.

Secrets are stored encrypted on the server and are never sent back to a browser.

Match accounts

An account is matched to the Active Directory user with the same email address or username, as set under Provisioning. The Accounts tab shows each account: Matched, Not matched, Two accounts (two accounts match one user, so neither is used until you select Use this one) or Not a person. Match to… matches an account by hand.

Give access with a rule

  1. Select Give access on an app, or Add a rule on the Access rules tab.
  2. Select the Active Directory group.
  3. For each app, select the groups and roles its members get. You can select several.
  4. Select whether members get them automatically or after you approve each one.
  5. What happens lists each change. Select Give access.

A member with no account gets one, unless that is turned off under Provisioning. Only direct members of the Active Directory group count.

Review changes

Review changes lists every difference between the rules and the apps: accounts to make, groups and roles to give, ones given by hand in the app, and what is blocked. Select what to apply. Taking a group or role away is never automatic. An account left in no group is disabled in the app.

Apps are read every 15 minutes. Two alerts are available under Alerts: a connected app stops syncing, and someone gets a role by hand in an app.

PowerShell scripts

An administrator of the server creates a folder under Connectors in the data folder and puts the scripts in it. The console selects the folder by name; it cannot upload or change a script. The scripts run as the Rabbid Lab service, so only place scripts you trust there.

  • Read.ps1 prints JSON: { "accounts": [{ "id", "name", "email", "login", "active" }], "groups": [{ "id", "name", "type", "members": ["account id"] }] }
  • New-Account.ps1 -Username -Name -Email -First -Last prints the new account's id.
  • Add-Member.ps1 and Remove-Member.ps1 take -Group and -Account.
  • Disable-Account.ps1 -Account

The optional secret is in $env:RABBIDLAB_SECRET. A script that fails must exit with a code other than 0. Each script has two minutes.

Permissions

View connected apps shows the page. Manage connected apps connects apps, matches accounts, changes rules and applies changes.

Create a group

  1. Open Groups and select New, or select New group from its arrow.
  2. Enter a name, and select the OU, the group scope (Global is typical) and the group type (Security for permissions, Distribution for email only).
  3. Select Create group.

Add or remove members

  1. Select the group. Its panel lists its members under Members.
  2. Select Add members, tick the users, groups or computers to add, then select Add members again to confirm.
  3. To remove a member, select the cross beside it.

You can also change a user's group memberships from their panel in Users.

Empty groups lists groups with no members, for cleanup.

Computers lists every computer account in the domain, including servers and workstations.

  1. Open Inactive (90+ days) to find computers that have not signed in to the domain recently.
  2. Select one, then select Actions > Account > Disable account. Domain users cannot sign in to the computer until the account is enabled again.
  3. If the computer is permanently retired, Delete it. To use it again, it must rejoin the domain.

Domain controllers are listed but cannot be changed here.

Each Active Directory page has views on the left, with the number of objects in each. Empty views are hidden, so the list shows what needs attention.

  • Users: Locked out, Expired passwords, Expiring passwords (within 14 days), Inactive (90+ days), Privileged accounts, Password never expires, Never signed in, and more.
  • Groups: Security, Distribution, Privileged, Empty groups.
  • Computers: Servers, Workstations, Inactive (90+ days), Disabled.

Search, at the top of the views, filters the list. Export saves the current list as a CSV file for Excel.

Domain health has its own entry in the navigation pane, under Directory. It checks the domain's configuration and objects against Microsoft, PingCastle and Defender for Identity recommendations. The checks are grouped into areas: passwords and lockout, privileged accounts, Kerberos and delegation, stale objects, domain and forest, domain controllers, certificates (AD CS), trusts and DNS. All data is read over LDAP with the Rabbid Lab service account, so nothing is installed on the domain controllers.

  1. Open Failed first. These checks need fixing.
  2. Select a check to open it in the panel on the right. It shows the current value, the recommended value and why it matters, and the affected objects (accounts, computers, groups, templates, trusts or zones).
  3. Select the arrow on an affected object to open it on its own page.

A GPO has no effect until it is linked to the domain or an OU. It then applies to the users and computers in that container and in the OUs below it.

  • Where linked lists the domain and every OU with the GPOs linked to each. Select one to see its links in order.

All access in Rabbid Lab is granted by roles. A user can have several roles and gets every permission those roles grant.

  • Administrator is the only role in tier 0 and has every permission. The server's local Windows administrators always have it.
  • User is in tier 2, and everyone who signs in has it.
  • Every other role is in tier 1 or tier 2.

Tiers

A role can be changed only by someone in a higher tier. The same goes for giving the role to someone, and for resetting the passwords and MFA of the people who have it. Someone with a tier 1 role can change and give tier 2 roles, if their permissions allow it, but not other tier 1 roles.

Tiers also apply in Active Directory. No one can reset the password of, or otherwise change, an account that has a role in their own tier or higher, or change a group that gives such a role. This prevents a help desk role from taking over an admin account.

A sensor runs one check on a schedule, from this server or through the client on a computer in Devices, and the Sensors page shows which sensors are down.

  1. Open Sensors and select Add a sensor.
  2. Select the check type:
    • Ping: the host responds to ping.
