Rabbid Lab runs on one machine (the server) and everyone uses it in a browser. Put it on a machine that stays on.

On Windows

  1. Download RabbidLab-Setup-<version>.exe from the latest release on GitHub.
  2. Run it and say yes to the admin prompt.
  3. Pick the folder and shortcuts, then the address (port 8420 unless you change it), then the HTTPS certificate. Rabbid Lab can make its own, or use one you already have.
  4. Click Install. Rabbid Lab installs as a Windows service and starts straight away.
  5. Open https://localhost:8420 on the server, or https://<server name>:8420 from another computer.

Running Setup again updates Rabbid Lab and keeps its settings.

In Docker

  1. Run docker compose up -d in the repository folder.
  2. Open http://<host>:8420. Everything Rabbid Lab keeps goes in the rabbidlab volume.

Next: set it up.

The first time anyone opens Rabbid Lab, it asks how people sign in. Do this right after installing: until it's done, anyone who can reach the port can do it.

With Active Directory

  1. Pick Active Directory.
  2. Check the domain, and leave the domain controller on Automatic unless you want a particular one.
  3. Sign in with your own domain account. You become an Administrator, and everyone in the domain can sign in as a User.

With a local account

  1. Pick Local account.
  2. Make a username and password. That account is the first Administrator.

Who gets what is up to you afterwards, under Roles.

Everything is in the rail down the left. You only see what your roles allow.

  • Lab: Overview and Links, the sites in your lab.
  • Active Directory: Users, Groups and Computers in your domain.
  • Config: Seats (the computers with the client), Local accounts on those computers, and Roles and people.
  • Help: this wiki, What's new, and GitHub.
  • Settings at the bottom: updates and the activity log.

Your name in the top right shows how you signed in and has Sign out. Collapse at the bottom shrinks the rail to icons.

A computer shows up under Seats once it has the Rabbid Lab client. There's no key: the client only needs the server's address. New computers wait until someone lets them in.

From the computer itself (easiest)

  1. On that computer, open Rabbid Lab in a browser and sign in.
  2. The bar at the top says it isn't in Seats yet. Click Download the client and run the MSI.
  3. Click Connect this computer. The client opens with this server's address filled in.
  4. Check the address, click Connect, and OK the admin prompt.
  5. Let it in under Seats.

Quietly, from a command line or Intune

  1. Open Seats and click Add computers.
  2. Copy the install line. It has this server's address, and the certificate fingerprint if the computers don't trust its certificate yet.
  3. Run it on the computer, or paste it into Intune as the install command.

With Group Policy

  1. In Add computers, download the MSI and the Group Policy template.
  2. Copy the template into PolicyDefinitions (the central store, or C:\Windows\PolicyDefinitions).
  3. In a GPO: Computer Configuration, Policies, Software Settings, Software Installation, assign the MSI.
  4. In the same GPO: Administrative Templates, Rabbid Lab, Client. Set Server address, and Server certificate fingerprint if you need it.

Group Policy wins over anything the installer or Connect was given.

  1. Open Seats. New computers show as Waiting.
  2. Click Let in on the computer. From then on it's a seat.
  3. To take a computer off, click Remove. If its client is still installed, it joins again and waits.

Don't want to let each one in? In Add computers, turn off New computers wait for an admin and they join straight away.

The All, Online, Offline, Waiting and Older client buttons above the list filter it.

The client is a small Windows service with a tray icon. It checks in every minute, says who is signed in, keeps itself on the server's version, and makes the account changes you ask for under Local accounts.

  • Its window: click the tray icon, or open Rabbid Lab Client from the Start menu. It shows whether the computer is connected, to which server, who is signed in to Windows, both versions and the last check-in.
  • When the icon shows: as soon as the client is installed by hand. After a quiet install (Intune, Group Policy) it shows at the next sign-in.
  • No server yet? The window has Connect to a server.
  • Stopping account changes on some computers: in the Group Policy template, set Allow account changes to Disabled.

If a seat won't take changes, see A seat that won't take changes.

Once a client has joined a server, uninstalling it on the computer is locked: Windows refuses, from installed apps and from the client's own window, until you allow it here. A client that never joined a server isn't locked.

  1. Open Seats and click Uninstall on the computer.
  2. Uninstall has the client take itself off within a minute. The computer then shows as Offline: click Remove to take it off the list.
  3. Or click Allow to let someone at the computer uninstall it for the next hour, from the client's window or from Windows' installed apps. Lock again ends that early.

The lock stops the ordinary ways of removing the client. Someone with administrator rights on the computer who sets out to tear it out by hand still can, and the seat then shows as Offline.

Rabbid Lab makes every Active Directory change as a dedicated service account, svc-rabbidlab. Its password is long, random and stored encrypted on the server. You set this up once.

Create a new one

  1. Open Users and click Set up. The steps run down the left: Sign in, Account, Review.
  2. Sign in: enter a domain admin username and password. They're only used to create the service account and aren't saved.
  3. Account: name it and pick the OU to create it in, from the list or with Browse….
  4. Review: check it, then click Create service account. Can manage starts as the whole domain; Change limits it to one OU.

The service account gets Full Control over user, group and computer objects there, the same as the Delegation of Control wizard.

Use one you have

Click Use one I have, sign in as the service account, then check it on Review. It needs permission to create and manage users, groups and computers where it works: the whole domain, or the OU you pick with Change.

Picking an OU

Browse… beside any OU list opens the OUs the way Settings lists its pages. An OU with OUs inside has the flask and opens when you click it. Type in Find an OU to search, then click Use this OU, or double-click it.

Change it later

Settings, Active Directory (the gear at the bottom of the views on any Active Directory page opens it) sets the default OU for new users and groups, and has Disconnect. Disconnecting deletes the stored password; the account and its permissions stay in AD until you delete them in Active Directory Users and Computers.

Admin accounts protected by AdminSDHolder (Domain Admins and the like) can be viewed but not changed by the service account.

  1. Open Users and click New user.
  2. Type the first and last name. The display name and username fill themselves in; change them if you like.
  3. Pick where it goes, and add an email, job title and description if you want.
  4. Leave Make one for me for the password, or pick Type one.
  5. Keep Change it at the first sign-in on, so the person picks their own.
  6. Add groups if you want, then click Make the account.
  7. Copy the password Rabbid Lab shows. It's shown once and not kept.
  1. Open Users, Locked out, or find the person in All users.
  2. Click them to open their card.
  3. Locked out? Click Unlock.
  4. Forgot their password? Click Set a password, pick Make one for me or type one, and keep Change it at the next sign-in on. Setting a password unlocks them too.
  5. Copy the new password and give it to them.

Click a row in Users, Groups or Computers to open it in a panel from the right: its details, its groups (and a group's members), and buttons for the everyday changes. Every row also has a menu with everything that can be changed: open it from ⋯ at the end of the row, or right-click the row.

  1. To change several at once, tick them on the left (Shift-click ticks a run of them), then click Actions in the toolbar. It shows how many are ticked.
  2. Pick a category: Account (enable, disable, unlock, expiration), Password, Groups, Security or Organization (edit properties, rename, move).
  3. Groups have Members (add, remove, copy from or to another group) and Member of. Computers have Account, Groups and Organization.
  4. The menu only lists what applies. With several picked, an item says how many of them it applies to.
  5. Add to groups, Add members, the Remove ones and Copy show everyone there is in a list with a tick each: find to narrow it, tick as many as you need (Tick all shown ticks everything the find left), and the count shows at the bottom. What they are already in, or who is already a member, is left out.

Protected and built-in accounts and groups can be changed too: Active Directory refuses whatever the service account isn't allowed to do. A few things are never offered: the password, sign-in settings and deleting of Rabbid Lab's own account (it would lock itself out), disabling, moving or deleting a domain controller, and deleting a built-in group. Every change goes in the Activity log.

  • The funnel button filters the list. It keeps the rows that match your conditions: pick a field (Department, Last sign-in, Member of group and so on), how to test it, and a value. Match all of them or any. The window shows how many match as you go. While a filter is on, the funnel shows how many conditions are on and the × beside it clears them.
  • Columns picks what the list shows, such as email, job title, office, manager, OU or password dates. Reset puts it back.
  • Click a column name to sort by it, and again to turn the order round. Drag the edge of a column name to make it wider or narrower; double-click the edge to fit the column to what is in it.
  • Rows, at the top of Columns, switches between Compact (the default) and Relaxed.

Every table in the console works the same way: Domain settings, AD audit, Recycle Bin, the Attribute browser, Seats and Signed in now too. Where a table has no toolbar, Columns is the icon at the right end of its heading row. Drag a heading onto another to move that column. Columns, order, widths and sort are kept in this browser for each table; Compact or Relaxed is one setting for all of them.

Someone left? Turn their account off first. It can be turned back on; deleting can't be undone.

  1. Open their card in Users.
  2. Click Turn off. They show under Disabled.
  3. When you're sure, open the card again and click Delete, then confirm.

Make a group

  1. Open Groups and click New group.
  2. Name it, pick where it goes, its scope (Global is usual) and its type (Security for permissions, Distribution for email only).
  3. Click Make the group.

Add or take out members

  1. Click the group. Its card lists who's in it.
  2. Type in Add a user, group or computer and click who you want.
  3. To take someone out, click the cross beside them.

You can also change a person's groups from their own card in Users.

Empty groups lists groups nobody is in, for tidying up.

Computers lists every computer account in the domain, servers and workstations.

  1. Open Inactive (90+ days) to find computers nobody has used in a while.
  2. Click one and Turn off its account. It can't sign anyone in with domain accounts until it's turned back on.
  3. Gone for good? Delete it. The computer would have to join the domain again.

Domain controllers are shown but can't be changed here.

Each Active Directory page has views down the left, with how many are in each. Views that would be empty stay hidden, so the list shows what needs looking at.

  • Users: Locked out, Expired and Expiring passwords (within 14 days), Inactive (90+ days), Privileged accounts, Password never expires, Never signed in, and more.
  • Groups: Security, Distribution, Privileged, Empty groups.
  • Computers: Servers, Workstations, Inactive, Disabled.

Find, at the top of the views, narrows the list. Export saves what's on screen as a CSV for Excel.

Domain settings has its own place in the left menu, under Directory. It shows how the domain is set up next to what's recommended. That covers passwords, lockout, Guest, krbtgt, Domain Admins, the functional levels, the domain controllers, the Recycle Bin and LAPS.

  1. Open Not as recommended first. Those are the ones worth fixing.
  2. Click a setting to see why it matters and where it's set (usually the Default Domain Policy).
  3. Change it there, then come back: the list reads the domain again each time you open it.

"Couldn't be read" means Rabbid Lab's account isn't allowed to see that one, which is normal for fine-grained password policies.

AD audit lists what changed in Active Directory in the last 30 days, wherever it was done: here, Active Directory Users and Computers, or PowerShell. Sign-ins and other housekeeping are left out, and so is a computer changing its own password.

  1. Pick a view: Last 24 hours, Made, Deleted, Users, and so on.
  2. Click a change to see which attributes changed.

When the change was made in Rabbid Lab, it says who made it. For changes made elsewhere, the domain controllers' security logs have that.

With the AD Recycle Bin on, a deleted user, group, computer or OU can come back as it was, groups and all, for 180 days (by default).

Turn it on (once)

  1. Open Recycle Bin. If it's off, click Turn it on.
  2. Sign in with an Enterprise Admin. It's used for this once and not kept.

It's for the whole forest, and it can't be turned off again. That's how Active Directory works.

Restore something

  1. Find it in Recycle Bin and click it.
  2. Click Restore. It goes back where it was.

Looking in Deleted Objects and restoring take rights only Domain Admins have by default. If Rabbid Lab's account doesn't have them, the page says so.

The Org chart draws who reports to whom from each person's Manager in Active Directory. Find highlights someone.

Nobody has a manager set? It shows everyone by department instead. Set Manager on the Organization tab in Active Directory Users and Computers, and the chart draws itself.

The Attribute browser shows the whole domain as folders, and every attribute of whatever you pick.

  1. Click an OU or container to go into it, and the path at the top to come back out.
  2. Click a user, group or computer to see its attributes. SIDs, GUIDs, dates and flags are shown in words.
  3. Type in Find an attribute or value to narrow the list. Hide empty shows only the attributes with a value; turn it off to see every one the object can have.
  4. Click … on an attribute, or right-click it, to copy it, or to Edit… or Clear value as ADSI Edit does. Editing needs the Edit attributes permission, works inside the service account's scope, and every change goes in the Activity log.
  5. The buttons at the top copy the object's distinguished name and export its attributes to a CSV file.

Passwords, LAPS passwords and BitLocker keys are never shown.

Local accounts are the Windows accounts on one computer: this server, or any seat. You do it all in the browser and no service account is needed: this server makes its own changes, and on a seat the Rabbid Lab client makes them, running as SYSTEM.

  1. Open Local accounts and pick the computer on the left. A green dot means it's ready.
  2. Click New account.
  3. Type the username, and a full name and description if you want.
  4. Pick the groups. Tick Administrators for a local admin; Users is ticked for you.
  5. Click Make the account. On a seat, its client makes it within a second or two.
  6. Copy the password Rabbid Lab shows.
  1. Open Local accounts, pick the computer, then click the account.
  2. Set a password also unlocks it.
  3. Turn off stops anyone signing in with it.
  4. Use the cross on a group, or Add to…, to change its groups.
  5. Delete removes it. Its files stay in its profile folder. Windows' own accounts, like Administrator, can only be turned off.

The dot beside each computer in Local accounts says whether it's ready: green is ready, amber is online but not ready, grey is offline. Hover it to see why.

  • It's offline: the computer is off, or can't reach the server.
  • Its client is older: it updates itself to the server's version within a few minutes.
  • Not listening yet: the client was just started or updated. Give it a minute.
  • Group Policy turns account changes off: Allow account changes is Disabled for that computer.

Everything in Rabbid Lab is allowed by roles. People can have several roles and get everything those roles allow.

  • Administrator is always at the top and allows everything. The server's Windows administrators are always in it.
  • User is always at the bottom, and everyone who signs in has it.

Make a role

  1. Open Roles and people and click New role.
  2. On Display, name it and pick a colour.
  3. On Permissions, switch on what it allows, part by part.
  4. On Members, add who's in it.
  5. Click Save changes.

Roles are in order, highest first: drag them to reorder. People can only change roles below their own highest one. Preview as shows what that role sees.

  1. Open Roles and people and click Add people.
  2. Search for an Active Directory group, a person, or a local account, and click it.
  3. Tick the roles, then click Add.

A group in a role counts for everyone in it, the next time they sign in. The + beside someone's roles gives them another one, and the cross on a role takes it away.

An Active Directory account that isn't in any role can't sign in. Everyone in AD is in User to begin with.

Local accounts in Rabbid Lab are its own sign-ins, separate from Windows and AD. Use them when there's no domain, or as a way in if AD is down.

  1. In Roles and people, click Add people, then New local account.
  2. Pick a username and a password of 8 characters or more, and its roles.

To sign in with one when AD is set up, pick Local account on the sign-in page, or type .\ before the username.

  1. Open Seats. Signed in now lists everyone signed in to Rabbid Lab, with their roles, browser and address.
  2. Click Sign out on someone to end their session straight away.
  1. Open Links and click Add a link.
  2. Paste the address, like https://192.168.2.23. Rabbid Lab reads the site and fills in the name, detail, icon and IP.
  3. Change anything you like, and pick a group to put it under. New group… at the bottom of the list makes one.
  4. Click Add the link.

Hover a link and click the pencil to change it or delete it. Upload sets your own icon, Letter shows the first letter of the name, and None leaves the tile with no icon at all.

To add several at once, click Add a link, then A list, and paste the addresses: one on each line, or separated by commas or semicolons. Each site is read for its name, icon and IP, and they all go in the group you pick. Addresses that are already on Links are left out.

The dot on each link says whether its site answers: green is up, amber didn't answer just now and is being tried again, red is down. Hover the dot for the detail. Any answer counts as up, a sign-in page included.

The cogwheel at the top of Links, beside Add a link, sets two things:

  • Heartbeat interval: 15 seconds to 5 minutes. A minute to begin with.
  • Show a link as down after no answer for: right away, or 15 seconds to 5 minutes. 30 seconds to begin with, so one slow reply doesn't turn a link red.

Links are checked while the console is open on the Links page. For checks around the clock, with email when something goes down, add a sensor.

The same cogwheel has Export and Import. Export saves every link with its icon, the groups in their order and these settings as one file. Import adds what's in a file like it beside what's already there: its groups, its links and its settings. A link whose address is already on Links is left as it is, so importing the same file twice adds nothing.

  • New group, at the end of the row above the links, makes an empty group.
  • Hover a group's name for its tools. Drag the handle to move the group up or down, click the pencil to rename it, and click the bin to delete it.
  • Deleting a group keeps its links. They move to No group at the bottom of the page.
  • To move a link to another group, hover it, click the pencil and pick the group.
  • Drag a link onto another group to move it there, or onto another link to put it beside that one: a line shows which side it lands on. To take it out of its group, drop it on No group, which shows at the bottom while you drag.
  • Open all, beside a group's name when you hover it, opens every link in the group in a tab of its own. Your browser stops all but the first until you allow pop-ups for the console.
  • Cards and Grid, at the right of the row above the links, switch between tiles and a row to a link. Your browser remembers which.
  • The filter button beside the search box shows one group at a time: click it and pick the group, or All groups to see everything again. It appears once there is more than one group to pick from, and past eight groups its menu has a search box.

A sensor checks one thing on a timer, from this server, and the Sensors page shows what's down.

  1. Open Sensors and click Add a sensor.
  2. Pick the check:
    • Ping: the machine answers.
    • Port: a port is open, such as 445 for file shares, 636 for LDAPS or 3389 for remote desktop.
    • Web page: the page answers. A sign-in page counts as up; an error 500 or higher counts as down.
    • DNS lookup: a name resolves, on the DNS server you name or the one this server uses.
    • Certificate: warns when a site's certificate has under 21 days left, and is down once it expires.
  3. Type the address. Check now tries it before you save.
  4. Pick a group, how often to check, and when it alerts, then click Add the sensor.

A sensor is down after two misses in a row, so one lost reply isn't an outage; change it with Down after. Its alerts go to the channels ticked under Send to: email, Discord, Teams, Slack, ntfy or any webhook, set up once in Settings, Notifications. Click a sensor for its history, to pause it, or to change it. The squares at the top of the page are the sensors: each beats when it's checked, and one that's down turns red.

  • Cards and Grid, at the right of the row above the sensors, switch between the two. Your browser remembers which.
  • The Rows view is a table like every other one: click a heading to sort, drag a heading onto another to move it, drag its right edge to resize, and Columns picks what shows and has Reset.
  • Groups work as they do on Links: drag a card onto another group to move it, New group, the filter button to show one group or only the sensors that are down, and hover a group's name to drag, rename or delete it.

Each sensor says when it alerts, under Alerts when you add or change it:

  • Alert when it has been down for: right away, 1 to 30 minutes, an hour, or never (it only shows on the page).
  • While it stays down: once, or again every hour, 6 hours or day.
  • When it comes back: an all-clear, only after a down alert went.
  • Depends on: while that sensor is down, this one waits instead of alerting, and shows as Waiting. If it's still down once the other is back, it alerts then.
  • Send to: email and the channels set up in Settings, Notifications. A kind that isn't set up yet can be set up from there.

New sensors start with what's set in Settings, Sensors. Use these alerts on other sensors copies one sensor's alerts to others; Use on every sensor in Settings does it for all of them. Something that comes back before its time is up alerts nobody.

On a sensor, Send a test alert sends its alert, marked as a test, to its channels. Pause stops it for 15 minutes, an hour, 4 hours, until 8 tomorrow or until you start it again, and can take what depends on it along. Gather alerts in Settings, Sensors sends one alert when several go down close together.

On Links, Watch it in a link's dialog gives it a sensor that checks it every minute and alerts the same way. Its dot comes from that sensor, and a small eye shows it's watched. Watch links in the bar above the links ticks many at once: tick them (or Tick all in a group), pick when to alert and where, and click Watch. Untick one to stop watching it.

Set up email under Settings, Notifications, with Edit on the Email row:

  • Gmail: your address and an app password (Google Account, Security, 2-Step Verification, App passwords).
  • Microsoft 365: an app registration in Microsoft Entra with the Mail.Send application permission and admin consent. Type the tenant, the application (client) ID and a client secret. From has to be a mailbox in the tenant.
  • Another mail server: any server or relay that takes STARTTLS on port 587.

Send a test email saves the settings and sends one to everyone on the list. Test on any channel's row sends it one. Passwords and secrets are stored encrypted on this server.

Settings, Console address lists where to open Rabbid Lab: this computer's names and IP addresses, and any you add. It also shows the HTTPS certificate, the port and the firewall rule.

  • Add an address gives the console a name of your own, such as lab. On a computer in a domain it can add an alias (CNAME) for it in DNS on a domain controller, with an account you type for that. The account needs DNS admin rights, and it isn't saved. It never changes a record that's already there, or takes a computer's name.
  • Not in a domain? Add the name on whatever answers DNS for your network, such as your router or Pi-hole. The dialog shows the record to add.
  • Added addresses get a certificate of their own, trusted on this computer. The console's own certificate doesn't change, so computers in Seats keep working. To open an added address from other computers without a warning, trust its certificate there too: Download it on the page.
  • Remove takes an address off, and its alias out of DNS if Rabbid Lab added it. Removing Rabbid Lab with everything takes the aliases out too.

The i at the top right gathers what someone helping you needs to know: the version, the machine, how it's installed, the sign-in domain, and how many seats, links and sensors there are. Click Copy and paste it into your message. It has no passwords in it, and only shows what your roles let you see.

Rabbid Lab checks GitHub for a new version on start, every 12 hours, and when you click Check for updates.

  • On Windows, a new version installs automatically once nobody has used Rabbid Lab for a couple of minutes. Turn that off with Update automatically under Settings, Updates.
  • Install now installs straight away. Rabbid Lab is stopped for about a minute while it installs.
  • Only updates signed with Rabbid Lab's release key install.
  • Seats update their client to the server's version by themselves.

In Docker, update with docker compose up -d --build.

Settings, Activity log lists every sign-in and change, who made it, and when. That covers accounts made, passwords set, groups changed, computers let in and updates installed. Passwords are never in it.

If nobody can get in (AD is down, or the last admin left), add a local administrator on the server itself:

  1. Open a command prompt as administrator on the server.
  2. Run "C:\Program Files\Rabbid Lab\RabbidLab.Server.exe" --add-admin admin
  3. Sign in with Local account, admin, and the password it prints.

In Docker: docker exec rabbidlab dotnet RabbidLab.Server.dll --add-admin admin

Everything is in one data folder: C:\ProgramData\Rabbid Lab on Windows, /data in Docker. Back it up to keep everything.

  • accounts.json: how people sign in, and Rabbid Lab's own accounts.
  • roles.json: roles, what they allow, and who's in them.
  • sessions.json: who's signed in, encrypted.
  • clients.json: the seats.
  • directory-tools.json: Rabbid Lab's AD account, its password encrypted.
  • links.json: the Links page.
  • activity.jsonl: the activity log.
  • Keys: the keys the encrypted parts use. Without them, the encrypted parts can't be read on another machine.
